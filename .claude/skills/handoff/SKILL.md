# handoff

このセッションの作業を、別のセッションがノートだけ読めば再開できる形で書き残す。
読み手は会話の文脈を一切持たない Claude だと想定する。

- 作業ノートの置き場所: `~/vault/obsidian/claude/work/`
- このセッションの ID: `${CLAUDE_SESSION_ID}`

## 1. 書き込み先のノートを決める

1. `grep -rlF '${CLAUDE_SESSION_ID}' ~/vault/obsidian/claude/work/` で、このセッションが既に載っているノートを探す。`status` が `done` 以外のノートが見つかればそれを更新する。`done` のノートしか見つからなければ、その作業の再開か別の作業かをユーザーに聞く
2. 該当がなければ、`status` が `done` 以外で `cwd` が今の作業ディレクトリと同じノートを探す。同じ作業の続きだと判断できればそれを更新する。判断がつかなければユーザーに聞く
3. どれにも当たらなければ新規作成する。ファイル名は `YYYY-MM-DD-<作業を表す短い名前>.md`（日付は今日）。名前に `/ \ : * ? " < > | # ^ [ ]` を含めない。同名のファイルが既にあれば別の名前にする

## 2. ノートを書く

新規作成時は下のテンプレートに従う。`title` `cwd` `branch` の値は、`:` や `#` を含んでも YAML として正しく読めるよう必ずダブルクォートで囲む。既存ノートを更新するときは次のように扱う。

- `現状` `次の一手` `未解決・注意点` は今の状態で書き直す（古い記述を残さない）
- `決定事項` は追記する。覆った決定は消さずに、覆った理由を添える
- `履歴` には今回のセッションの分を1行足す
- frontmatter の `sessions` に `${CLAUDE_SESSION_ID}` が無ければ追加し、`updated` を今の時刻にする

```markdown
---
title: "<作業の名前>"
status: active
cwd: "<作業ディレクトリの絶対パス>"
branch: "<git ブランチ。git 管理外なら空>"
created: <YYYY-MM-DD>
updated: <YYYY-MM-DDTHH:mm:ss>
sessions:
  - ${CLAUDE_SESSION_ID}
---

## 目的

<何のための作業か。ユーザーの元の依頼と、その背景>

## 現状

<どこまで終わったか。変更したファイル、コミット済みか否か、動作確認の結果>

## 次の一手

<再開したら最初にやること。具体的なコマンドやファイル名で書く>

## 決定事項

- <決めたこと>: <理由。却下した案があればそれも>

## 未解決・注意点

<ユーザーの判断待ち、ハマった点、触ってはいけないもの>

## 履歴

- YYYY-MM-DD: <このセッションでやったこと1行>
```

`status` は次のどれか。

- `active`: 続きがある
- `paused`: ユーザーの判断待ちや外部要因で止まっている
- `done`: 完了した。この場合も `現状` に最終状態を書く

## 3. 書く内容の基準

- 会話を読まなくても分かるように書く。「さっきの件」「例のファイル」のような指示語は使わず、パスやコマンドで書く
- コードやコミットから読み取れることは繰り返さない。リポジトリを見ても分からない経緯・判断・ユーザーの意向を優先する
- 推測と事実を分ける。確認していないことは「未確認」と書く

## 4. 報告

書いたノートのパスと `status` をユーザーに1〜2行で伝える。
